# Confidentiality and Data Compliance Guide

This project is intended for interview demonstration with synthetic content.

## Required rules

- Use synthetic or publicly shareable sample documents only.
- Keep all API keys, tokens, and secrets out of git.
- Use `.env` locally; commit only `.env.example` placeholders.
- Use fictional property, tenant, and company names in examples and outputs.

## Do not include

- Real customer names or identifiers
- Logos, confidential screenshots, or proprietary UI captures
- Internal documents, contracts, or appraisal reports
- Credentials, private endpoints, or non-public URLs

## Safe demo content checklist

- CLI examples run on generated synthetic PDFs (`re-rag create-sample-data`).
- Outputs are citation-backed from synthetic sources only.
- Architecture visuals are diagrams, not screenshots of sensitive systems.

## Interview handling guidance

- If asked to discuss real customer experience, keep details anonymous and
  generalized.
- Do not paste customer snippets into prompts, notebooks, or terminal history.
- If uncertain whether content is shareable, exclude it.
